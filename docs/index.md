# Strettch Cloud Provider

The Strettch Cloud provider lets you manage your Strettch Cloud infrastructure
with Terraform, through the [Strettch Cloud API](https://cloud.strettch.com/docs/api-reference/introduction).

## Example Usage

```terraform
terraform {
  required_providers {
    strettchcloud = {
      source = "strettch-cloud/strettchcloud"
    }
  }
}

provider "strettchcloud" {
  # api_key defaults to the STRETTCH_CLOUD_API_KEY environment variable.
  # api_url defaults to the production API.
}
```

## Authentication

The provider authenticates with an API key, sent as `Authorization: Bearer <key>`.
Provide it with the `api_key` argument or, preferably, the
`STRETTCH_CLOUD_API_KEY` environment variable:

```shell
export STRETTCH_CLOUD_API_KEY="<your api key>"
```

On HCP Terraform, set `STRETTCH_CLOUD_API_KEY` as a **sensitive** workspace
environment variable.

## Schema

### Optional

- `api_key` (String, Sensitive) API key for authentication, sent as `Authorization: Bearer <key>`. May also be set with the `STRETTCH_CLOUD_API_KEY` environment variable.
- `api_url` (String) Base URL of the Strettch Cloud API. Defaults to the production URL. May also be set with the `STRETTCH_CLOUD_API_URL` environment variable.
- `http_retry_max` (Number) Maximum number of retries after the first attempt for retryable failures. Defaults to `4`. May also be set with `STRETTCH_CLOUD_HTTP_RETRY_MAX`.
- `http_retry_wait_max` (Number) Maximum backoff, in seconds, between retries. Defaults to `30`. May also be set with `STRETTCH_CLOUD_HTTP_RETRY_WAIT_MAX`.
- `http_retry_wait_min` (Number) Minimum backoff, in seconds, before the first retry. Defaults to `1`. May also be set with `STRETTCH_CLOUD_HTTP_RETRY_WAIT_MIN`.
- `requests_per_second` (Number) Client-side rate limit, in requests per second. Defaults to `2`, the API ceiling; higher values are capped to `2`. May also be set with `STRETTCH_CLOUD_REQUESTS_PER_SECOND`.

### Tuning

`api_url` overrides the API endpoint and is rarely set; it defaults to the
production API. The rate-limit and retry options (`requests_per_second`,
`http_retry_max`, `http_retry_wait_min`, `http_retry_wait_max`) are also rarely
set; the defaults match the API's limits.

## Capturing logs for support

The provider logs through Terraform's structured logger, silent by default. To
capture logs when reporting a problem:

```shell
TF_LOG_PROVIDER=DEBUG TF_LOG_PATH=terraform.log terraform plan   # or apply
```

Attach `terraform.log` to the support ticket. Each request logs a `requestId`
that lets us find the matching call in our API logs. The API key is never logged.

## Known limitations

- **No downsizing.** `specification` can only be raised; lowering it is an error.
  Replace the compute if you need a smaller size.
- **A resize stops the compute.** Raising `specification` stops the compute during
  the resize, then starts it again if its configured state is `RUNNING`. Expect a
  short outage.
- **`public_keys` is not recoverable on import.** After `terraform import`, the
  first apply writes `public_keys` from your configuration in place (never a
  replace). SSH keys and the public IP cannot change after creation.
- **No user-data yet.**
- **Terraform 1.14+** is required for Terraform Search (list resources) and the
  reboot action; the rest works with any current Terraform.
