# Strettch Cloud Provider

The Strettch Cloud provider lets you provision and manage your
[Strettch Cloud](https://cloud.strettch.com) resources as declarative Terraform
configuration, backed by the
[Strettch Cloud API](https://cloud.strettch.com/docs/api-reference/introduction).
Configure it with an API key to get started.

Browse the resources and data sources in the navigation on the left.

## Example Usage

```terraform
terraform {
  required_providers {
    strettchcloud = {
      source  = "strettch-cloud/strettchcloud"
      version = "~> 1.0"
    }
  }
}

provider "strettchcloud" {
  # api_key defaults to the STRETTCH_CLOUD_API_KEY environment variable.
}

# Provision a compute instance.
resource "strettchcloud_compute" "web" {
  host_name      = "web-01"
  image          = "UBUNTU-24.04"
  region         = "KGL-1"
  specification  = "S-1C-2G"
  public_keys    = ["ssh-ed25519 AAAA..."]
  with_public_ip = true
}
```

## Authentication

The provider authenticates with an API key, sent as `Authorization: Bearer <key>`.
Provide it with the `api_key` argument or, preferably, the
`STRETTCH_CLOUD_API_KEY` environment variable:

```shell
export STRETTCH_CLOUD_API_KEY="<your api key>"
```

On HCP Terraform, set `STRETTCH_CLOUD_API_KEY` as a **sensitive** workspace
environment variable.

## Capturing logs for support

The provider logs through Terraform's structured logger, silent by default. To
capture logs for a `plan` or `apply` when reporting a problem:

```shell
TF_LOG_PROVIDER=DEBUG TF_LOG_PATH=terraform.log terraform plan
```

Attach `terraform.log` to the support ticket. Each request logs a `requestId`
that lets us find the matching call in our API logs. The API key is never logged.
